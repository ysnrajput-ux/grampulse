# Live connection error: root-cause findings

## What was verified

On 10 October 2026, `https://grampulse-ten.vercel.app/api/health` returned HTTP 503 with `{code:"SERVICE_UNAVAILABLE"}`. The static site returned HTTP 200. The deployed response is generated by the `api/index.js` initialization catch; it is not an API route/CORS response produced by the Express application.

## Root cause in the shipped code

The Vercel adapter converted every startup failure into one generic 503, preventing diagnosis. Before Express could register `/api/health`, it had to import the compiled application, connect to persistence, and run the migration. In this codebase, no `DATABASE_URL` causes `connect()` to select embedded PGlite and write under `DATA_DIR` (default `data/postgres`), which is local development storage and is not a durable or reliable Vercel database. A missing database environment variable, database network/TLS failure, or migration SQL omitted from the function bundle could all produce the observed initialization 503.

The live environment variables and Vercel Function logs are not accessible from this workspace, so I cannot honestly distinguish which of those startup failures occurred in the live project. The previously shipped generic handler erased that distinction. The most likely configuration fault is missing/invalid `DATABASE_URL`; check the matching deployment's Function log to confirm. The changes now return `DATABASE_NOT_CONFIGURED` when it is absent and log a request-safe initialization detail for other startup failures.

There was also a separate production mutation blocker: with `APP_ORIGIN` unset, the API defaulted to `http://localhost:3000`, rejecting same-origin POST/PATCH/DELETE calls made from the deployed site. The API now derives the request origin behind Vercel when the explicit variable is unset; an explicit `APP_ORIGIN` remains supported.

## What remains external

A managed PostgreSQL service must be configured in Vercel as `DATABASE_URL`, and its schema must be migrated. This workspace has no access to that database or Vercel project settings. The deployment has not been changed from this workspace. Photo uploads use local disk and are now explicitly disabled on Vercel with `UPLOAD_STORAGE_NOT_CONFIGURED`; citizen reports without photos continue to work. Durable private object storage needs a separate adapter before photo uploads can be enabled in production.


## Subsequent deployment check (11 October 2026)

The originally named URL `https://grampulse-ten.vercel.app/` now returns Vercel HTTP 404 `DEPLOYMENT_NOT_FOUND` for both `/` and `/api/health` from this environment. This is a deployment/domain availability result, not an application-level API or password response. A separate Vercel host previously shown in the user's screenshot returned a healthy `/api/health`, but no hosted login was attempted. Verify the current Visit URL in the user's Vercel project and deploy the corrected source there.
